# 01. Обзор проекта

Документ фиксирует общую картину системы: состав, границы первой версии, ключевые
инженерные решения и структуру репозитория. Является входной точкой для разработчиков
прошивки и мобильного приложения.

Источник требований: [`bike-tz.md`](../bike-tz.md).

---

## 1. Что делаем

Автономный велокомпьютер на руль + Android-приложение-конфигуратор.

```text
       ┌─────────────┐   магнитное поле    ┌────────────────────────────┐
       │ Магнит      │────────────────────▶│ Датчик Холла (цифровой)    │
       │ на спице    │  1 импульс/оборот   │ открытый коллектор → D0    │
       └─────────────┘                     └──────────────┬─────────────┘
                                                          │ GPIO IRQ
                                          ┌───────────────▼──────────────┐
                                          │  XIAO nRF52840 Sense         │
                                          │  ─ измерение скорости        │
                                          │  ─ дистанция / одометр       │
                                          │  ─ время движения, avg/max   │
                                          │  ─ конфигурация в LittleFS   │
                                          │  ─ BLE GATT Peripheral       │
                                          └──┬────────────────────────┬──┘
                                     I²C     │                        │  BLE
                                  ┌──────────▼─────────┐   ┌──────────▼──────────┐
                                  │ OLED SSD1306 128×32│   │ Android (Flutter)   │
                                  └────────────────────┘   │ монитор/настройка/  │
                                                           │ диагностика/сервис  │
                                                           └─────────────────────┘
```

Ключевой принцип: **велокомпьютер полностью автономен**. Телефон — только конфигуратор
и диагностический терминал. Отсутствие телефона не влияет ни на одну основную функцию
(ТЗ §29).

## 4. Ключевые инженерные решения (сводка)

Полное обоснование — в [07-decisions-and-risks.md](07-decisions-and-risks.md).

1. **Целочисленная арифметика в горячем пути.** Скорость и дистанция считаются в
   фиксированной точке (`0.01 км/ч`, миллиметры). Float допускается только в слое
   отображения и калибровке батареи. Причина: ТЗ §3.4 (запрет FP в ISR), исключение
   накопления ошибок округления в одометре (ТЗ §4.4).
2. **ISR минимальна.** Обработчик прерывания пишет `micros()` в lock-free ring buffer и
   инкрементирует счётчик. Вся фильтрация, расчёты, дисплей, Flash и BLE — в основном цикле.
3. **Кооперативный планировщик, без блокирующих задержек.** Набор задач с периодами
   (`display`, `battery`, `ble_notify`, `storage`, `state`) вместо `delay()`.
4. **Бинарный BLE-протокол** с версионированием `major.minor`, little-endian, фиксированными
   размерами полей. JSON не используется даже в прототипе, чтобы не платить за миграцию
   (ТЗ §33 допускает JSON, но переход обязателен — делаем сразу).
5. **Двухслотовое (A/B) хранение** конфигурации и одометра с CRC32 и монотонным
   счётчиком записи. Гарантирует атомарность и откат к валидному слоту при повреждении.
6. **Разделение «настройки» и «счётчики»** по разным файлам: настройки меняются редко,
   одометр — часто. Это ограничивает износ Flash и упрощает восстановление.
7. **Write-then-verify в приложении.** Запись конфигурации считается успешной только
   после подтверждения от устройства и повторного чтения (ТЗ §30).
8. **Единицы измерения — только на уровне отображения.** Внутри устройства и в протоколе
   всё метрическое; imperial — флаг форматирования (ТЗ §23).

## 5. Единицы измерения и точность (общий словарь)

| Величина | Внутреннее представление | В протоколе | На экране |
| --- | --- | --- | --- |
| Скорость | `uint16 speed_x100`, 0.01 км/ч | `uint16` | `24.8 km/h` (0.1) |
| Дистанция поездки | `uint32 trip_mm` | `uint32 trip_cm` | `18.42 km` |
| Одометр | `uint64 odo_mm` | `uint32 odo_m` | `1234 km` |
| Время движения | `uint32 moving_ms` | `uint32 moving_s` | `01:12:36` |
| Окружность колеса | `uint16 mm` (500…3000) | `uint16` | `2100 mm` |
| Напряжение АКБ | `uint16 mv` | `uint16 mv` | `3.92 V` |
| Заряд | `uint8 percent` | `uint8` | `82%` |

Границы полей: одометр `uint64` в мм покрывает любой ресурс устройства; в протоколе
`uint32` в метрах даёт 4 294 967 км — достаточно.

## 6. Глоссарий

| Термин | Значение |
| --- | --- |
| Импульс (pulse) | Одно срабатывание датчика Холла = один оборот колеса |
| Корректный импульс | Импульс, прошедший фильтр debounce/минимального интервала/лимита скорости |
| Поездка (trip) | Набор сбрасываемых счётчиков: дистанция, время движения, avg, max |
| Одометр (odometer) | Накопительный пробег, сбрасывается только защищённой командой |
| Автопауза | Переход в состояние «остановка» по тайм-ауту отсутствия импульсов |
| Страница (page) | Один вариант содержимого нижней строки OLED |
| Карусель | Автоматическое переключение страниц по таймеру |
| Слот (A/B) | Одна из двух копий персистентной записи для атомарного обновления |
| Токен подтверждения | Одноразовый nonce для опасных BLE-команд |

## 9. Определение готовности v1.0

Релиз v1.0 закрывается только при одновременном выполнении:

1. Все 17 критериев приёмки прошивки (ТЗ §42) — подтверждены протоколами тестов.
2. Все 15 критериев приёмки приложения (ТЗ §43) — подтверждены.
3. Погрешность скорости ≤ 2 % на эталонном стенде и в поездке (ТЗ §42.5).
4. Полевые испытания: ≥ 3 поездки суммарно ≥ 60 км без потери данных и зависаний.
5. Документы `protocol/*` соответствуют коду (проверяется golden-тестами на фикстурах).
6. Собран подписанный release-APK и `firmware.uf2`/`.hex` с зафиксированными версиями
   библиотек в `platformio.ini`.
