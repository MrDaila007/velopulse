Обоснование выбора датчика: DRV5032 (1.8–5.5 В, микроамперное потребление, цифровой выход)
снимает главную проблему классического A3144 — постоянный ток 5–8 мА, который на батарее
500 мА·ч даёт менее 4 суток простоя. Полный разбор в ADR-002.

### 1.1. Требование к частоте опроса датчика (критично)

Низкопотребляющие Hall switch'и работают в импульсном режиме: внутренний генератор
периодически включает чувствительный элемент. Магнит находится в зоне обнаружения очень
недолго, поэтому частота опроса задаёт нижнюю границу пригодности датчика.

```text
Оценка окна обнаружения:
  зона срабатывания по дуге          ≈ 20 мм (магнит 6 мм + гистерезис по обе стороны)
  линейная скорость магнита на радиусе установки при 30 км/ч  ≈ 8.3 м/с
  длительность окна = 0.020 / 8.3    ≈ 2.4 мс
  при 50 км/ч                        ≈ 1.4 мс
```

Отсюда требования при выборе конкретного варианта датчика:

* частота внутреннего опроса **≥ 1 кГц** (окно 1.4 мс должно попасть минимум на один опрос);
* варианты DRV5032 с опросом 20 Гц (период 50 мс) **пропустят почти каждый проход магнита** —
  использовать нельзя, несмотря на привлекательные 0.54 мкА;
* варианты с опросом 2.5 кГц (период 0.4 мс) дают 3–6 опросов за окно — надёжно;
* непрерывные (не импульсные) датчики вроде A3144 по частоте подходят всегда, вопрос только
  в потреблении.

При закупке проверяется по datasheet: `Sampling rate` / `Output update rate` конкретного
суффикса варианта. Значение фиксируется в `hardware/bom.md`. Проверка на стенде —
пункт 6 таблицы §7 (отсутствие потерь импульсов на эквиваленте 60 км/ч).

Магнит увеличенного размера (или два магнита, расположенных рядом как один «широкий») окно
удлиняет, но менять число магнитов на колесе нельзя — один импульс должен соответствовать
одному обороту (ТЗ §2.4).

## 2. Схема соединений

```text
         Li-Po 3.7 V                          ┌──────────────────────────┐
         ┌──────┐                             │  OLED SSD1306 128×32     │
         │  +   ├──────── BAT+ ──┐            │  VCC  GND  SCL  SDA      │
         │  −   ├──────── BAT− ──┤            └───┬────┬────┬────┬───────┘
         └──────┘                │                │    │    │    │
                                 │            3V3 ┘    │    │    │
     ┌───────────────────────────▼────────────┐        │    │    │
     │      XIAO nRF52840 Sense               │        │    │    │
     │                                        │        │    │    │
     │  3V3 ─────────────────────────────┬────┼────────┘    │    │
     │  GND ─────────────────────────────┼────┼─────────────┘    │
     │  D5 / SCL ────────────────────────┼────┼──────────────────┘    │
     │  D4 / SDA ────────────────────────┼────┼───────────────────────┘
     │                                   │    │
     │  D0  ◀─── OUT ── Hall sensor      │    │
     │  3V3 ───── VCC ── (DRV5032)       │    │
     │  GND ───── GND ──                 │    │
     │                                   │    │
     │  USB-C: зарядка + прошивка + Serial    │
     └────────────────────────────────────────┘

   Подтяжка D0: внутренняя INPUT_PULLUP (по умолчанию)
              либо внешний 4.7–10 кΩ на 3V3 (для длинного кабеля предпочтительно)
   Дополнительно: 100 нФ между VCC и GND у датчика
```

### 2.2. Обязательная проверка распиновки

Имена внутренних пинов (батарея, разрешение делителя, статус зарядки) различаются между
версиями board-пакета. **До написания `battery_manager.cpp`** необходимо:

1. Найти `variant.h`/`variant.cpp` для `seeed-xiao-afruitnrf52-nrf52840` в установленном
   `~/.platformio/packages/framework-arduinoadafruitnrf52/variants/`.
2. Выписать фактические определения (например `PIN_VBAT`, `VBAT_ENABLE`, `PIN_CHARGING_CURRENT`,
   `PIN_HICHG`, `PIN_CHG`) в `include/board_pins.h` c комментарием-ссылкой на файл и версию.
3. Подтвердить эмпирически: измерить напряжение АКБ мультиметром и сравнить с расчётом ADC
   при трёх уровнях заряда; занести коэффициенты в defaults калибровки.
4. Зафиксировать результат в `hardware/wiring.md`.

Это отдельная задача этапа Э1 (см. план работ), без неё индикация заряда не считается
готовой.

## 3. Измерение напряжения аккумулятора

* Встроенный резистивный делитель на плате XIAO (номинально 1 МΩ / 510 кΩ) →
  коэффициент ≈ 2.96. Точное значение уточняется калибровкой.
* ADC: 12 бит, внутреннее опорное 0.6 В, gain 1/4 → полная шкала 2.4 В.
* Порядок измерения: разрешить делитель → ожидание 2 мс → 16 выборок → отбросить min/max →
  среднее → пересчёт в мВ → калибровка (`scale_permille`, `offset_mv`) → EMA-фильтр.
* Делитель включается только на время измерения (иначе постоянный ток утечки ≈ 2.5 мкА,
  что тоже приемлемо, но экономия бесплатна).

Требуемая точность: ±50 мВ в диапазоне 3.3–4.2 В после калибровки — достаточно для
индикации процента с шагом 1 % по таблице OCV.

## 4. Зарядка

* Встроенный контроллер XIAO (BQ25100 или аналог в зависимости от ревизии).
* Ток зарядки переключается пином HICHG: 50 мА (по умолчанию) или 100 мА.
  Для АКБ 500–1000 мА·ч рекомендуется **100 мА** (0.1–0.2C) — безопасно и в 2 раза быстрее.
  Настраивается один раз в `setup()`.
* Заряд от USB-C. Время полного заряда 500 мА·ч при 100 мА ≈ 6 ч.
* Индикация: статус зарядки читается с пина CHG (LOW = идёт зарядка на большинстве ревизий);
  при невозможности достоверного чтения передаётся `charge_status_unknown` (ТЗ §8.1).

## 5. Механика установки

### 5.1. Датчик на вилке

```text
       вилка                     спица
         │                         │
    ┌────┴────┐             ┌──────┴──────┐
    │ датчик  │◀── 2..8 мм ─│   магнит    │
    │ (метка) │             │ (метка ↕)   │
    └─────────┘             └─────────────┘
    метки маркированных сторон должны быть обращены друг к другу
```

Требования (ТЗ §2.4):

* Зазор 2–8 мм; целевое значение **3–5 мм** — компромисс между надёжностью срабатывания
  и риском контакта при биении колеса.
* Отсутствие механического контакта при максимальном биении: проверяется прокруткой колеса
  и покачиванием.
* Датчик ориентирован чувствительной стороной к магниту; для униполярного DRV5032FA важна
  полярность магнита — если срабатываний нет, магнит переворачивается.
* Один магнит на колесо → один импульс на оборот (ТЗ §2.4). Установка двух магнитов
  недопустима без изменения прошивки.
* Кабель фиксируется стяжками с петлёй запаса у выхода из корпуса (защита от вырывания),
  не касается тормозного диска и покрышки.

### 5.2. Корпус на руле

* Крепление на руль 22.2 мм: хомут или силиконовые стяжки; поворот дисплея не требуется.
* Дисплей должен читаться при типовом угле обзора сверху 30–60°.
* Класс защиты: минимум IP54 (дождь, брызги). Разъём USB-C закрыт заглушкой/мембраной.
* Внутри — виброизоляция АКБ (поролон 2 мм) и разгрузка проводов.
* Антенна nRF52840 на модуле не должна прилегать к металлу; в корпусе обеспечить
  зазор ≥ 5 мм от металлических элементов руля.

## 6. Энергетический бюджет

| Режим | Компоненты | Ток |
| --- | --- | --- |
| Движение | MCU active + OLED вкл + BLE медленная реклама | 8–12 мА |
| Короткая остановка | то же, обновление 1 Гц | 6–9 мА |
| Idle, OLED выкл | MCU sleep между тиками + реклама 1000 мс | 0.6–1.5 мА |
| Подключение BLE | + активное соединение 15–60 мс | +1–3 мА |
| Deep sleep (если включён) | System OFF + GPIO SENSE | 10–30 мкА |
| Зарядка | — | вход 100 мА |

Расчётная автономность при 500 мА·ч:

| Сценарий | Оценка |
| --- | --- |
| Непрерывная езда | 40–60 ч |
| 1 ч езды в день + остальное idle (OLED выкл) | ~2 недели |
| Хранение с deep sleep | месяцы |
| Хранение без deep sleep (idle 1 мА) | ~20 дней |

Вывод: без глубокого сна устройство остаётся практичным, но требует зарядки при длительном
простое — это делает deep sleep желательной, но не блокирующей функцией (ТЗ §10.2, ADR-009).

## 7. Проверки этапа аппаратного прототипа (ТЗ §35)

| № | Проверка | Критерий приёмки |
| --: | --- | --- |
| 1 | XIAO прошивается и виден в PlatformIO | `pio run -t upload` успешен, Serial отвечает |
| 2 | I²C-скан находит дисплей | Адрес `0x3C` (или `0x3D`) обнаружен |
| 3 | Дисплей выводит тестовый текст | Читаемо, без артефактов, контраст управляется |
| 4 | Датчик Холла даёт импульсы | При проносе магнита уровень меняется; счётчик растёт на 1 за проход |
| 5 | Отсутствие дребезга | На 10 медленных проходах ровно 10 импульсов (после фильтра) |
| 6 | Работа на скорости | На стенде/раскрутке колеса до эквивалента 60 км/ч импульсы не теряются |
| 7 | АКБ подключён, полярность верна | Устройство работает от батареи, напряжение соответствует |
| 8 | Зарядка работает | Ток заряда измерен, напряжение растёт, статус читается |
| 9 | Расчёт напряжения по ADC | Расхождение с мультиметром ≤ 50 мВ после калибровки |
| 10 | Зазор датчик–магнит | Устойчивое срабатывание при 2 и при 8 мм, без контакта |

Результаты фиксируются в `hardware/wiring.md` с фотографиями в `hardware/images/`.

## 8. Известные аппаратные риски

| Риск | Проявление | Меры |
| --- | --- | --- |
| Ложные срабатывания от вибрации | Скачки скорости, завышенная дистанция | Цифровой Hall switch с гистерезисом, debounce, лимит скорости, фильтр «залипания» |
| Пропуск импульсов на высокой скорости | Заниженная скорость/дистанция | Ring buffer в ISR, отсутствие блокировок в основном цикле, проверка на стенде |
| Магнит смещается | Пропадание сигнала | Держатель с двойной фиксацией, контроль после первых 50 км |
| Просадка напряжения от OLED | Скачки процента заряда | EMA + компенсация IR-drop + монотонность процента |
| Некорректная распиновка АКБ в core | Неверный заряд или отсутствие показаний | Обязательная сверка `variant.h` + эмпирическая калибровка (§2.2) |
| Влага в корпусе | Отказ, коррозия | IP54, заглушка USB, конформное покрытие платы датчика |
| Обрыв кабеля датчика | Нет импульсов | Разъём JST, петля запаса, диагностика `SENSOR_NO_SIGNAL` в приложении |
