# 02. План разработки

Детальный план работ по этапам с задачами, критериями завершения (DoD) и оценками.

Оценки — в **человеко-днях** (ч.-д.) для одного разработчика полного дня. Разработка
прошивки и приложения после этапа Э4 может идти параллельно двумя людьми; в одиночку
последовательность сохраняется.

Требования-источники: ТЗ §35–§41 (этапы), §44–§45 (MVP), §42–§43 (приёмка).

## 3. Управление изменениями протокола

1. Любая правка структур начинается с PR в `protocol/`.
2. PR обязан содержать: обновлённую таблицу полей, инкремент `minor`/`major`, новые/изменённые
   фикстуры.
3. После мержа — синхронные PR в прошивку и приложение; сборка обеих сторон должна
   проходить golden-тесты на новых фикстурах.
4. Нарушение порядка (правка кода до документа) считается дефектом процесса.

## 4. Отслеживание прогресса

* Каждая задача плана = issue с меткой этапа (`stage:E2`) и подсистемы (`fw`/`app`/`hw`).
* Критерии приёмки ТЗ §42/§43 = отдельные issue с меткой `acceptance`, закрываются только
  по факту проверки на устройстве с приложением протокола (см.
  [06-testing-and-acceptance.md](06-testing-and-acceptance.md)).
* Milestone закрывается только когда закрыты все его DoD-пункты.
