# Техническое задание

## Компактный велокомпьютер на XIAO nRF52840 Sense и мобильное приложение-конфигуратор

## 1. Общая информация

### 1.1. Назначение проекта

Разработать компактный автономный велокомпьютер, устанавливаемый на руль велосипеда и выполняющий следующие функции:

* измерение текущей скорости;
* подсчёт дистанции поездки;
* расчёт средней и максимальной скорости;
* измерение времени движения;
* хранение общего пробега;
* автоматический старт и пауза;
* отображение информации на OLED-дисплее;
* настройка устройства через Bluetooth Low Energy;
* просмотр текущих параметров устройства в мобильном приложении;
* обновление пользовательских настроек без перепрошивки устройства.

### 1.2. Основной принцип работы

На спице колеса устанавливается постоянный магнит. На вилке велосипеда устанавливается цифровой датчик Холла.

При каждом прохождении магнита датчик формирует импульс. Микроконтроллер измеряет время между импульсами и рассчитывает скорость.

Расстояние увеличивается на значение окружности колеса при каждом корректно зарегистрированном обороте.

### 1.3. Первая версия проекта

В первую версию входят:

* XIAO nRF52840 Sense;
* OLED SSD1306 128×32;
* цифровой датчик Холла;
* Li-Po аккумулятор;
* BLE-конфигуратор;
* автоматическое управление без физических кнопок.

В первую версию не входят:

* GNSS;
* карты и навигация;
* запись маршрута;
* датчик каденса;
* датчик пульса;
* ANT+;
* синхронизация со Strava;
* Wi-Fi;
* физические кнопки;
* сенсорный экран.

# Часть 1. Велокомпьютер

## 2. Аппаратная платформа

### 2.1. Микроконтроллер

Использовать:

**Seeed Studio XIAO nRF52840 Sense**

Основные используемые возможности:

* микроконтроллер Nordic nRF52840;
* Bluetooth Low Energy;
* GPIO с аппаратными прерываниями;
* I²C;
* внутренние таймеры;
* внутренняя Flash-память;
* ADC для измерения аккумулятора;
* встроенная зарядка Li-Po;
* встроенный IMU — опционально в последующих версиях.

Встроенный микрофон в первой версии не используется.

### 2.2. Дисплей

Использовать OLED-дисплей:

* контроллер SSD1306;
* разрешение 128×32 пикселя;
* интерфейс I²C;
* питание 3,3 В;
* адрес по умолчанию `0x3C`;
* монохромный;
* предпочтительный цвет — белый.

Подключение:

| SSD1306 | XIAO nRF52840 Sense |
| ------- | ------------------- |
| VCC     | 3V3                 |
| GND     | GND                 |
| SDA     | D4 / SDA            |
| SCL     | D5 / SCL            |

Допускается другой адрес дисплея при возможности изменить его в конфигурации прошивки.

### 2.3. Датчик Холла

Использовать цифровой датчик Холла с логическим или open-drain выходом.

Предпочтительные характеристики:

* питание 3,3 В;
* малое собственное потребление;
* цифровой выход;
* возможность работы с постоянным магнитом;
* устойчивость к вибрациям;
* рабочий температурный диапазон не уже −10…+50 °C.

Подключение:

| Датчик Холла | XIAO |
| ------------ | ---- |
| VCC          | 3V3  |
| GND          | GND  |
| OUT          | D0   |

Для open-drain выхода использовать:

* внутреннюю подтяжку `INPUT_PULLUP`, либо
* внешний резистор 4,7–10 кОм к 3,3 В.

Если применяется аналоговый датчик семейства 49E, он рассматривается только как временный вариант прототипа. Для конечной версии предпочтителен цифровой Hall switch.

### 2.4. Магнит

Использовать один магнит на спице.

Требования:

* надёжная фиксация;
* расстояние до датчика при прохождении — ориентировочно 2–8 мм;
* отсутствие контакта с датчиком;
* магнит не должен смещаться при вибрации;
* один импульс датчика должен соответствовать одному обороту колеса.

### 2.5. Питание

Использовать одноэлементный Li-Po аккумулятор:

* номинальное напряжение 3,7 В;
* рекомендуемая ёмкость 500–1000 мА·ч;
* встроенная зарядка через XIAO;
* подключение с соблюдением полярности.

Устройство должно отображать приблизительный уровень заряда аккумулятора.

Требуется программная калибровка зависимости напряжения от процента заряда.

* установить флаг нового импульса.

В обработчике прерывания запрещено:

* обновлять дисплей;
* записывать Flash;
* выполнять BLE-передачу;
* выполнять вычисления с плавающей точкой;
* выводить данные в Serial.

## 4. Измерение скорости и дистанции

### 4.1. Настройка окружности колеса

Окружность колеса задаётся в миллиметрах.

Диапазон:

* минимум: 500 мм;
* максимум: 3000 мм;
* значение по умолчанию: 2100 мм.

Настройка производится через BLE-приложение.

### 4.2. Расчёт скорости

При одном магните на колесе:

```text
speed_kmh = wheel_circumference_mm × 3.6 / pulse_interval_ms
```

Скорость рассчитывается после каждого корректного импульса.

### 4.3. Фильтрация импульсов

Прошивка должна отбрасывать:

* импульсы с интервалом меньше заданного минимального значения;
* импульсы, соответствующие скорости выше установленного лимита;
* повторные импульсы, вызванные дребезгом или длительным нахождением магнита рядом с датчиком.

Настраиваемые параметры:

* максимальная допустимая скорость;
* минимальный интервал импульса;
* тайм-аут установки скорости в ноль.

Значения по умолчанию:

* максимальная скорость: 100 км/ч;
* тайм-аут нулевой скорости: 3 секунды;
* минимальный интервал импульса вычисляется из окружности колеса и максимальной скорости.

### 4.4. Расчёт дистанции

После каждого корректного импульса:

```text
trip_distance += wheel_circumference
odometer += wheel_circumference
```

Для внутренних расчётов дистанция должна храниться в целых миллиметрах или оборотах, чтобы избежать накопления ошибок округления.

Для отображения значения преобразуются в километры.

### 4.5. Текущая скорость

Текущая скорость:

* обновляется после каждого оборота;
* отображается с точностью 0,1 км/ч;
* устанавливается в `0,0 км/ч`, если импульсы отсутствуют дольше заданного тайм-аута;
* может дополнительно сглаживаться по последним 2–3 оборотам.

Сглаживание должно быть отключаемым через приложение.

## 5. Логика поездки

### 5.1. Автоматический старт

Поездка автоматически переводится в состояние движения после первого корректного импульса.

Отдельное ручное включение не требуется.

### 5.2. Автоматическая пауза

Если импульсы отсутствуют дольше заданного времени:

* текущая скорость устанавливается в ноль;
* время движения перестаёт увеличиваться;
* поездка переходит в состояние паузы.

Значение по умолчанию:

* 3 секунды.

### 5.3. Время поездки

Устройство должно хранить:

* время движения;
* общее время с момента начала поездки — опционально;
* время текущей остановки — для внутренней логики.

Средняя скорость рассчитывается по времени движения:

```text
average_speed = trip_distance / moving_time
```

### 5.4. Максимальная скорость

Максимальная скорость обновляется при превышении текущего сохранённого значения.

Максимальная скорость должна сохраняться до сброса текущей поездки.

### 5.5. Сброс поездки

Так как физических кнопок нет, сброс выполняется через BLE-приложение.

При сбросе обнуляются:

* дистанция текущей поездки;
* время движения;
* максимальная скорость;
* средняя скорость;
* время начала поездки.

Общий одометр не сбрасывается обычной командой сброса поездки.

Для сброса одометра требуется отдельная защищённая команда с подтверждением.

## 6. Отображаемые параметры

Устройство должно рассчитывать и отображать:

* текущую скорость;
* дистанцию текущей поездки;
* среднюю скорость;
* максимальную скорость;
* время движения;
* общий одометр;
* заряд аккумулятора;
* статус BLE;
* статус датчика Холла.

### 6.1. Основной экран

Основное значение — текущая скорость.

Пример:

```text
┌─────────────────────┐
│ 24.8 km/h       [82%]│
│ MOV TRIP 18.42 km    │
└─────────────────────┘
```

Текущая скорость отображается постоянно. В правом верхнем углу постоянно
отображаются иконка аккумулятора и процент заряда. Автоматически меняется только
нижняя строка.

### 6.2. Автоматическое переключение информации

Так как кнопок нет, нижняя строка автоматически переключается.

Последовательность:

1. дистанция поездки;
2. средняя скорость;
3. максимальная скорость;
4. время движения;
5. общий одометр.

Период переключения должен настраиваться через BLE.

Значение по умолчанию:

* 4 секунды.

### 6.3. Настройка состава экранов

В приложении должна быть возможность:

* включить или выключить отдельные страницы;
* изменить порядок страниц;
* выбрать постоянную страницу;
* включить или отключить автоматическое переключение.

Первая версия допускает фиксированный порядок страниц, если изменение порядка существенно усложняет реализацию.

---

## 7. Управление дисплеем

### 7.1. Частота обновления

Основной экран должен обновляться:

* 4 раза в секунду во время движения;
* 1 раз в секунду во время короткой остановки;
* не обновляться после отключения дисплея.

### 7.2. Автоматическое выключение

После остановки дисплей должен отключаться через заданный тайм-аут.

Значение по умолчанию:

* 60 секунд.

Настраиваемый диапазон:

* 10–600 секунд;
* режим «никогда не выключать».

### 7.3. Автоматическое включение

Дисплей включается при:

* корректном импульсе датчика Холла;
* подключении BLE-приложения;
* изменении настроек;
* выполнении команды теста дисплея.

### 7.4. Яркость

SSD1306 должен поддерживать настройку контрастности.

Диапазон в приложении:

* 1–100%.

Прошивка преобразует процент в значение контроллера SSD1306.

---

## 8. Измерение аккумулятора

### 8.1. Параметры

Устройство должно передавать:

* напряжение аккумулятора;
* приблизительный процент заряда;
* статус зарядки, если его можно достоверно определить.

### 8.2. Фильтрация

Напряжение аккумулятора должно усредняться по нескольким измерениям.

Не допускается резкое изменение отображаемого уровня из-за одиночного измерения.

### 8.3. Предупреждение

При низком заряде:

* на дисплее отображается предупреждение;
* BLE-приложение получает соответствующий статус.

Порог низкого заряда настраивается.

Значение по умолчанию:

* 20%.

---

## 9. Хранение данных

### 9.1. Сохраняемые параметры

Во Flash сохраняются:

* общий одометр;
* окружность колеса;
* параметры фильтрации;
* тайм-аут остановки;
* тайм-аут дисплея;
* яркость;
* период переключения экранов;
* выбранные страницы;
* имя устройства;
* калибровка аккумулятора;
* настройки BLE;
* версия структуры конфигурации.

### 9.2. Сохранение одометра

Одометр не должен записываться после каждого оборота.

Запись выполняется:

* после накопления заданной дистанции;
* при длительной остановке;
* перед переходом в глубокий сон;
* после BLE-команды;
* при критически низком заряде.

Рекомендуемый интервал записи:

* каждые 500 или 1000 метров.

### 9.3. Защита Flash

Необходимо:

* минимизировать количество циклов записи;
* использовать атомарное сохранение;
* хранить контрольную сумму;
* поддерживать версию формата;
* восстанавливать настройки по умолчанию при повреждении данных.

## 10. Энергосбережение

### 10.1. Режимы

Предусмотреть состояния:

1. активное движение;
2. короткая остановка;
3. ожидание;
4. глубокий сон;
5. BLE-настройка;
6. зарядка.

### 10.2. Глубокий сон

После длительного отсутствия движения устройство может переходить в низкопотребляющий режим.

Значение по умолчанию:

* 15 минут.

Пробуждение:

* импульсом датчика Холла;
* подключением USB;
* другим поддерживаемым аппаратным событием.

В первой версии допускается не реализовывать глубокий сон, если стандартный Arduino core не обеспечивает стабильное пробуждение от выбранного GPIO. Функция должна быть предусмотрена архитектурно.

### 10.3. BLE-реклама

BLE-реклама должна работать:

* постоянно с увеличенным интервалом, либо
* только ограниченное время после запуска и движения.

Рекомендуемый режим первой версии:

* медленная постоянная реклама;
* ускоренная реклама в течение 30 секунд после пробуждения.

# Часть 2. BLE-протокол

## 11. Общие требования

Велокомпьютер должен работать как BLE Peripheral.

Мобильное приложение работает как BLE Central.

Использовать собственный GATT-сервис конфигурации.

Все UUID должны быть задокументированы и зафиксированы в общем файле спецификации.

## 12. BLE-сервис

Рабочее название:

**Bike Computer Configuration Service**

Сервис должен содержать характеристики:

1. информация об устройстве;
2. текущая телеметрия;
3. чтение конфигурации;
4. запись конфигурации;
5. команды управления;
6. результат команды;
7. журнал ошибок — опционально.

## 13. Характеристика информации об устройстве

Режим:

* Read.

Содержит:

* модель устройства;
* версия аппаратуры;
* версия прошивки;
* версия BLE-протокола;
* серийный идентификатор;
* время работы;
* причина последней перезагрузки.

Допускается формат JSON для прототипа или компактная бинарная структура для основной версии.

Рекомендуется бинарный формат с явно заданными размерами полей.

## 14. Характеристика телеметрии

Режим:

* Read;
* Notify.

Поля:

* текущая скорость;
* дистанция поездки;
* средняя скорость;
* максимальная скорость;
* время движения;
* общий одометр;
* напряжение аккумулятора;
* процент заряда;
* состояние движения;
* состояние датчика Холла;
* состояние дисплея;
* счётчик оборотов;
* RSSI соединения — на стороне приложения.

Рекомендуемая частота уведомлений:

* 1 раз в секунду при открытом экране мониторинга;
* реже либо отключено в фоне.

## 15. Характеристика конфигурации

Режим:

* Read;
* Write;
* Write with response.

Параметры:

* окружность колеса;
* максимальная допустимая скорость;
* тайм-аут нулевой скорости;
* тайм-аут выключения экрана;
* тайм-аут глубокого сна;
* яркость;
* период переключения нижней строки;
* включённые страницы;
* сглаживание скорости;
* интервал записи одометра;
* порог низкого заряда;
* имя устройства;
* единицы измерения;
* постоянная BLE-реклама;
* автоматическое выключение OLED.

После записи конфигурации устройство должно:

1. проверить диапазоны;
2. отклонить некорректные данные;
3. сохранить корректные настройки;
4. применить настройки;
5. вернуть результат операции.

## 16. Командная характеристика

Режим:

* Write with response.

Команды:

* сброс текущей поездки;
* сброс максимальной скорости;
* принудительное сохранение;
* включение дисплея;

* сброс одометра;

Опасные команды требуют отдельного подтверждения:

* сброс одометра;
* заводской сброс;
* перезагрузка;
* изменение калибровки аккумулятора.

## 17. Безопасность BLE

Первая версия должна поддерживать:

* BLE pairing;
* bonding;
* сохранение доверенного телефона;
* запрет изменения конфигурации без сопряжения.

Опционально:

* разрешить подключение только одному доверенному устройству;
* режим временного открытия для нового сопряжения;
* PIN-код;
* подтверждение нового сопряжения через USB или специальную процедуру.

Так как физических кнопок нет, первичное сопряжение допускается в течение ограниченного времени после включения.

Рекомендуемый режим:

* первые 5 минут после включения разрешено новое сопряжение;
* затем устройство принимает только ранее сохранённые связи;
* повторное открытие сопряжения выполняется через USB-команду или сброс настроек.

Для прототипа допускается постоянная возможность сопряжения.

# Часть 4. Совместная разработка

## 32. Версионирование протокола

BLE-протокол должен иметь номер версии.

Формат:

```text
major.minor
```

Правила:

* изменение `major` означает несовместимое изменение;
* изменение `minor` означает обратимо совместимое расширение.

Приложение должно проверять версию протокола после подключения.

При несовместимой версии:

* чтение базовой информации разрешается;
* запись конфигурации блокируется;
* пользователь получает предупреждение.

---

## 33. Формат данных

Для первой версии рекомендуется бинарный формат.

Преимущества:

* компактность;
* меньше BLE-пакетов;
* меньше расход энергии;
* однозначные размеры полей.

Все многобайтовые значения должны использовать little-endian.

Для каждого пакета указываются:

* версия структуры;
* тип сообщения;
* длина;
* полезные данные;
* контрольная сумма — опционально, так как BLE уже имеет контроль целостности.

Для прототипа допускается JSON, но переход на бинарный протокол должен быть предусмотрен до стабильного релиза.

# Часть 6. Критерии приёмки

## 42. Критерии приёмки прошивки

Первая версия считается работоспособной, если:

1. Устройство стабильно запускается.
2. SSD1306 128×32 отображает данные.
3. Каждый оборот колеса регистрируется один раз.
4. Ложные импульсы фильтруются.
5. Скорость рассчитывается с погрешностью не более 2% при корректной окружности колеса.
6. Дистанция сохраняется после перезагрузки.
7. Одометр не сбрасывается при сбросе поездки.
8. Автоматический старт работает.
9. Автоматическая пауза работает.
10. OLED выключается после остановки.
11. Новый оборот включает OLED.
12. Уровень аккумулятора отображается.
13. Устройство доступно по BLE.
14. Настройки читаются и записываются.
15. Некорректные настройки отклоняются.
16. Сброс поездки выполняется через BLE.
17. Прошивка продолжает считать поездку без телефона.

## 43. Критерии приёмки приложения

Приложение считается работоспособным, если:

1. Находит велокомпьютер по BLE.
2. Подключается к устройству.
3. Повторно подключается после разрыва.
4. Отображает текущую скорость.
5. Отображает дистанцию и время.
6. Показывает заряд аккумулятора.
7. Читает текущую конфигурацию.
8. Изменяет окружность колеса.
9. Изменяет параметры OLED.
10. Изменяет тайм-ауты.
11. Выполняет сброс поездки.
12. Показывает результат каждой команды.
13. Не отправляет некорректные значения.
14. Обрабатывает несовместимую версию протокола.
15. Показывает понятные сообщения об ошибках.
